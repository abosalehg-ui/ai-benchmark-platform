## 1. نظرة عامة سريعة

منصة ويب محلية لمقارنة نماذج الذكاء الاصطناعي على بنشماركات جاهزة (برمجة، رياضيات، معرفة عامة، واستخدام أدوات) مع تركيز أصيل على المحتوى العربي والسعودي (150 سؤالاً موثّق المصدر في الأنظمة والفقه + 25 سؤال لهجات). البنية **monolith من طبقتين**: خادم FastAPI يُنظّم التشغيل ويبثّ النتائج لحظياً عبر SSE، وواجهة Vanilla JS تُقدَّم كملفات ثابتة من نفس الأصل. البيانات كلها محلية في SQLite، ومفاتيح الـ API تبقى في `localStorage` المتصفح وتُمرَّر مع كل طلب تشغيل.

**التقنيات:** Python 3.10+ · FastAPI + Uvicorn · Pydantic v2 · httpx (async) · SQLite (stdlib، WAL) · Vanilla JS/CSS بلا build step · Chart.js 4.4 من CDN · Docker/subprocess كـ sandbox لتنفيذ الكود · pytest + ruff + GitHub Actions (مصفوفة 3.10/3.11/3.12).

**نقاط قوة حقيقية يجب عدم المساس بها:** الفصل الطبقي عبر `BaseProvider`/`BaseBenchmark` مع registries و factories (`backend/providers/__init__.py:15`، `backend/benchmarks/__init__.py:15`) — إضافة مزوّد جديد = ملف + سطر؛ عزل Docker جادّ وليس صورياً (`docker_runner.py:56-72`)؛ فاصل ثقة Wilson (`db.py:17`) بدل الفاصل التقليدي؛ retry موحّد يحترم `Retry-After` (`_http.py:47`)؛ والتوثيق العربي (README + CONTRIBUTING + قوالب Issues/PR) استثنائي لمشروع بهذا الحجم.

### 2.4 معالجة الأخطاء والحالات الحدّية — **6 / 10**

**🔴 لا يوجد `logging` في المشروع إطلاقاً.** تحقّقت: `grep -rn "logging\|logger" backend/` = صفر نتائج. كل خطأ يُحوَّل إلى نص ويُرجَع للعميل، ولا يُسجَّل شيء على الخادم. عند فشل تشغيل في الإنتاج لا يوجد أي أثر للتشخيص. **الحل:** `logging.getLogger(__name__)` في `runner`/`providers`/`db`، مع `logger.exception()` في كل `except Exception`، و**حظر صريح** على تسجيل `api_key` أو `prompt` كاملاً.

**🔴 خطأ حقيقي — تعارض بين الدقة المعروضة وفاصل الثقة:** في `db.py:213` تُحسب `accuracy = AVG(raw_score)`، بينما في `db.py:225` يُحسب فاصل الثقة من `wilson_interval(n_correct, n)` أي من `correct` الثنائية. عند بنشماركات لا يكون فيها `raw_score` ثنائياً:
- `tool_use.py:130` → `raw_score` قد يساوي **0.5** (الأداة صحيحة والمعاملات خاطئة)
- `llm_judge.py:131` → `raw_score = (score-1)/4` أي **0.0/0.25/0.5/0.75/1.0**

النتيجة: الواجهة تعرض `78.5% ± 12.3` حيث الـ 78.5% مقياس مستمر والـ ±12.3 مشتق من مقياس ثنائي مختلف تماماً. **الرقمان لا ينتميان لنفس الكمية.** (`app.js:679-684`)
**الحل:** إمّا حساب الفاصل من نفس المقياس (bootstrap CI للمتوسط المستمر)، أو عرض عمودين منفصلين صراحةً: «الدقة الثنائية (CI)» و«المتوسط المرجّح» — مع تسمية واضحة أيّهما.

**🟠 خطأ يسبب استثناء:** `db.py:179-180` — `kwargs.get("response_text", "")[:5000]`. لو مُرِّر `response_text=None` صراحةً فالقيمة الافتراضية لا تُستخدم و`None[:5000]` يرفع `TypeError` يُسقط الـ run كاملاً. حالياً `runner.py:197` يمرّر `score.model_response` (افتراضيها `""`) فالمسار آمن، لكنه اعتماد هشّ على مستدعٍ واحد. **الحل:** `(kwargs.get("response_text") or "")[:5000]` وكذلك لـ `judgment`.

**🟠 `preexec_fn` غير آمن مع الخيوط:** `subprocess_runner.py:76` يستخدم `preexec_fn=_apply_rlimits`، و`humaneval.py:68` يستدعي الـ sandbox عبر `asyncio.to_thread` — أي **من داخل خيط**. توثيق CPython صريح: `preexec_fn` غير آمن في وجود خيوط وقد يؤدي إلى deadlock بعد `fork` إذا كان خيط آخر يمسك قفلاً. مع `RUN_CONCURRENCY=5` هذا سيناريو متعدّد الخيوط دائماً.
**الحل:** استبدله بتشغيل launcher صغير: `[sys.executable, "-c", "import resource,runpy;<setrlimit>;runpy.run_path(...)"]` — يُطبّق الحدود **بعد** exec بلا fork-hook. بديل أنظف: `resource.prlimit()` من الأب بعد `Popen`.

**🟡 ابتلاع الأخطاء:** `except Exception` عارية في 9 مواضع (`docker_runner.py:109`, `subprocess_runner.py:93`, وكل مزوّد) تُحوّل كل شيء — بما فيه `MemoryError` و`KeyboardInterrupt` غير المقصودة — إلى نص خطأ. مع غياب logging، الأثر مفقود نهائياً.

**🟡 الواجهة بلا حراسة:** `app.js:74-85` (`loadBenchmarks`, `loadProviders`) بلا `try/catch`، على عكس `loadSandboxStatus` (`app.js:62`) التي تعالج الفشل. لو سقط الخادم، `init()` يرمي rejection غير معالَج وتبقى الصفحة **فارغة بلا أي رسالة** للمستخدم.
**الحل:** غلّف `init()` بـ try/catch يعرض banner «تعذّر الاتصال بالخادم — تأكد أنه يعمل على المنفذ 8000».

**🟡 حالات حدّية غير مغطّاة:**
- `main.py:136-139` — الفلترة قد تُرجع صفر مسائل؛ `/api/estimate` يعالجها بلطف، لكن `/api/run` (`runner.py:107`) **لا يعالجها**: ينشئ run بـ `n=0`، يبثّ `start` ثم `model_done` بدقة `0/max(0,1)=0.0`، ويظهر للمستخدم «صفر بالمئة» بدل «لا توجد مسائل مطابقة».
- `tool_use.py:68` — الـ regex `\{(?:[^{}]|(?:\{[^{}]*\}))*\}` يدعم **مستوى تداخل واحداً فقط**؛ أي `arguments` بها كائن داخل كائن يفشل الاستخراج ويُحسب خطأً على النموذج. موثّق كحدّ في المراجعة السابقة لكنه لم يُصلَح. **الحل:** ماسح أقواس متوازن بسيط (عدّاد عمق) بدل regex.

### 4.7 إعدادات CORS و Headers الأمنية — **5 / 10**

**✅ CORS مضبوط بمسؤولية:** `main.py:37-45` — أصول محدّدة (لا `*`)، طرق محدّدة، headers محدّدة، وقابل للتوسيع عبر env مع تعليق يشرح ذلك. أفضل من أغلب المشاريع المشابهة. (ملاحظة: لا `allow_credentials=True` — صحيح، فلا توجد كوكيز.)

**🟠 لا يوجد أي رأس أمني.** فحصت `main.py` كاملاً: لا CSP، لا `X-Content-Type-Options`, لا `X-Frame-Options`, لا `Referrer-Policy`, لا `Permissions-Policy`.

- غياب **CSP** هو ما يحوّل XSS في §4.2 من «مزعج» إلى «سرقة اعتمادات»: بلا `connect-src` مقيّد، حمولة الـ XSS تستطيع `fetch()` إلى أي نطاق خارجي.
- غياب **`X-Frame-Options`/`frame-ancestors`** يسمح بوضع الصفحة في iframe → clickjacking على أزرار الحذف/التشغيل.
- `Referrer-Policy` مهم هنا تحديداً لأن الصفحة تُحمّل موارد من ثلاث جهات خارجية (§4.6) وترسل لها الـ Referer.

**الحل (middleware واحد، ~12 سطراً):**
```python
@app.middleware("http")
async def security_headers(request, call_next):
    r = await call_next(request)
    r.headers["Content-Security-Policy"] = (
        "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; "
        "img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'"
    )
    r.headers["X-Content-Type-Options"] = "nosniff"
    r.headers["Referrer-Policy"] = "no-referrer"
    r.headers["X-Frame-Options"] = "DENY"
    return r
```
(يتطلّب استضافة Chart.js والخطوط محلياً أولاً — وهو مطلوب أصلاً لبنود D3/D4.)

**🟡 تحصين Docker sandbox — نقاط متبقّية** (`docker_runner.py:56-72`): العزل ممتاز أصلاً (`--network=none`, `--read-only`, `--user=65534`, `--pids-limit`, `no-new-privileges`, `--rm`) لكن ينقصه:
- `--cap-drop=ALL` — الحاوية تعمل بالقدرات الافتراضية.
- `--tmpfs=/tmp:size=64m,exec` (سطر 65) يسمح صراحةً بـ **exec** على `/tmp` — يُبطل جزئياً فائدة `--read-only`. أزل `exec` إن لم يكن مطلوباً لـ `pip`.
- لا `--security-opt seccomp=...` مخصّص (الافتراضي مقبول لكن يمكن تضييقه).

### ملاحظات على حدود هذه المراجعة (لتجنّب الافتراض)

- **لم أشغّل الخادم ولا الواجهة في متصفح.** كل ملاحظات UX/RTL/الاستجابة مستنتجة من قراءة HTML/CSS/JS وحساب التباين برمجياً، لا من فحص بصري حيّ. ملاحظات مثل تصرّف `ar-SA` مع التقويم الهجري تعتمد على سلوك `Intl` المعروف وقد تختلف بين المتصفحات.
- **لم أتحقّق من صحّة الأسعار في `pricing.py`** مقابل مواقع المزوّدين الرسمية — خارج نطاق قراءة الكود.
- **لا يوجد قياس تغطية في المشروع**، فلم أذكر أي نسبة تغطية؛ ما ذكرته هو عدد الاختبارات (29) ونتيجة تشغيلها (28 نجحت / 1 تخطّي) والفجوات المُتحقَّق منها بالبحث في ملف الاختبارات.
- **لم أتحقّق من مزوّدي الـ API الفعليين** (لا مفاتيح متاحة)، فصحّة تحليل الاستجابات لثمانية مزوّدين غير مُختبَرة عملياً — وهي بالضبط الفجوة رقم 16.
